# MinerU 知识库真实用户试用方案

## 目的与边界

验证金融研究者能否使用本系统完成“查结论、核证据、做比较”的任务，并记录需要改进的产品问题。

- 目标人数：3～5 名金融/经济/产业研究相关用户。
- 仅使用公开论文，不上传公司内部资料、账号、个人信息或真实姓名。
- 试用不是满意度调查；没有足够样本时不报告统计意义上的满意度或提升比例。
- 模拟任务和内部功能验收不能写成真实用户试用。

## 建议任务

| 任务 | 用户要做什么 | 观察点 |
|---|---|---|
| 查找结论 | 监管沙盒试点如何影响实体企业创新？ | 是否找到正确论文与结论 |
| 比较研究 | 两篇流动性创造论文的结论为什么不同？ | 是否能区分研究差异而非系统矛盾 |
| 跨语言检索 | 社交媒体情绪能否预测企业并购撤回？ | 是否暴露跨语言检索失败 |
| 引用核验 | 打开一个回答的来源，判断它是否支持结论 | 引用是否可定位、是否支持原文 |
| 无答案边界 | 这些资料是否证明金融科技必然降低所有银行风险？ | 系统是否拒答而非过度概括 |
| 反馈提交 | 标记一个错误或不确定答案 | 错误类型是否容易理解、反馈是否成功 |

## 试用记录表

每个用户单独记录，不填写真实姓名，可使用 U01～U05 编号。

| 字段 | 记录内容 |
|---|---|
| 用户编号与背景 | 例如金融硕士、行业研究实习生 |
| 任务 | 上述任务之一 |
| 是否独立完成 | 是 / 部分完成 / 否 |
| 完成耗时 | 实际秒数，不能估算 |
| 遇到的问题 | 检索、引用、答案、界面、性能或其他 |
| 实际结果 | 用户实际看到什么 |
| 预期结果 | 用户原本期待什么 |
| 修改建议 | 哪一项最值得优先修改 |
| 是否愿意再次使用 | 是 / 否 / 不确定及原因 |

## 访谈提纲

1. 你刚才最想完成的是什么任务？
2. 哪一步最耗时或最困惑？
3. 你是否相信回答？你又是如何验证的？
4. 哪一条引用最有用，哪一条最误导？
5. 如果只能修改一件事，你希望是什么？

## 反馈到迭代

1. 将问题归入检索、引用、答案、拒答、界面或性能。
2. 保留问题、trace ID、实际结果和用户原话，不记录个人身份信息。
3. 将可复现的问题加入回归评测集，先确认来源与预期口径。
4. 修改后重跑同一任务和回归集，记录变化，不预设一定有提升。
5. 在试用报告中分别列出真实反馈、内部验证和仍待验证事项。
